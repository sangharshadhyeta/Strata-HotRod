The idea

A model far bigger than the card, placed by use

A mixture-of-experts model uses only a small slice of itself for each word. So the busiest experts sit on the card, the next busiest in RAM and the rest on the drive, and the placement keeps changing as the conversation does. Watch one layer's experts being requested.

One layer's experts 
hot · on the card · 12 GB · 254 GB/s warm · in RAM · 30 GB · 24.5 GB/s over PCIe cold · on the SSD · up to 111 GB · 3.55 GB/s stand-in · a hot expert doing a missing one's work

Each request is served from the card, from a stand-in, from RAM or from the SSD, and an expert that was read moves up a tier.

Chapter 1

Don't wait for the expert: serve a stand-in

When the model asks for an expert that is not on the card, the engine can wait for it or run a similar one that is already there. This is the lever that mattered most.

solid.cpp · what it found

On a model that does not fit, a stand-in was the largest single gain. Qwen3.8-Flash-Next (87 GB) on the 12 GB card, same binary, tokens per second:

Expert cache off3.7
Cache on, no stand-ins8.3
Cache on + stand-ins12.85
A model that fits (Gemma-4 26B)72–78

Pushed too far, stand-ins wreck the text: at the most aggressive setting the model produced "a question to how a steps explaining on the how quicksort" at a respectable-looking 11.95 tok/s. So speed alone could never be the test. Three of solid.cpp's own safety checks were also wrong, and each correction changed how HotRod measures:

CheckWhat it measuredVerdict
ReproducibilityIdentical greedy answers across 5 repeats. The cache changes between requests, so wording drifts.Fired 9 times, always at 2-of-5: sampling noise. Removed
Fidelity scoreSimilarity to a stand-in-free reference. A stand-in differs by design.Rated a correct answer at zero. Demoted to a report
DegeneracyRepeated 4-grams, one word dominating.Caught the only real memory bug. Kept

A setting that passed every short test later returned an empty answer when served with reasoning on. Quick tests may only shortlist; the decision is taken in the setup that is actually served.

became

Strata-HotRod · what was built

Stand-ins by confidence, not by rank. A missing expert is replaced only when router weight × logit gap ≤ budget: a heavy pick needs a stand-in within about a logit, a light one can take one much further away. The budget tunes itself by alternating runs of the same text, each request brakes itself if re-checks show flips, and the few fragile tokens are re-run exactly.

The line was measured, then the answers were read. Short answers, warm, tokens per second on the 3060 PC:

Chapter 2

Guess ahead, but only if the guess arrives on time

Knowing which experts the next layer will want lets the engine start the reads early. solid.cpp tried it twice and learned which kind of guess pays.

solid.cpp · what it found

solid.cpp trained a small predictor (a "pre-router") on its own traffic and tried three ways of using its guesses. Tokens per second:

What the guess was used forGemma-4 26BQwen3.8-Flash-Next
Trained, but not used—9.44
Fetch experts before they are asked for (admission)56.59 hurts9.45 adds nothing
Protect likely experts from eviction71.419.86
Eviction + prefer wanted experts as stand-ins52.81 hurts10.69
Router look-aheadRuns as a graph node while the current layer computes. Lead time: exactly one layer. Arrives every time.
Trained pre-routerQueued on a worker, one deep, and drops rather than falls behind. Arrives whenever, or never.

The guess that can be late helped keep the right experts; it did not help fetch new ones. A related trick, biasing the router toward experts already on the card, lifted the hit rate from 0.847 to 0.917 (+3.9% speed). A predictor trained live on a CPU thread, in the earlier experiments, lost outright.

became

Strata-HotRod · what was built

A learned look-ahead that runs on the card. It starts from the model's own router and learns a small correction, one, two and four layers ahead, so the guess is never worse than the router's. It runs on the graphics card while the current layer computes, so it arrives on time, and the reads it starts use two I/O threads, next layer first: only about 3,000 of 25,000 experts read ahead were being used, and eight threads' wasted reads had queued in front of the real ones.

+8% code+15% reasoning+8% prosedrive wait 3.8–4.7 s → 2.8–3.0 s

On DeepSeek, where a missing expert is computed on the CPU, the same guesses feed a VRAM ring: spare card slots filled one or two layers ahead, used only if the copy has landed.

Chapter 3

Make everything fit, and keep the reads cheap

The drive, not the arithmetic, sets the speed. solid.cpp found that its worst slowdowns were its own bugs and its own memory budget.

solid.cpp · what it found

Two bugs had been blamed on the hardware. The page first said the PC was the limit. The loader was page-locking memory-mapped experts on a model larger than RAM, turning 18.4 GiB into copies that could not be evicted, and every page fault read 4 MiB for a 0.88 MiB expert slice. Fixing both took the same model on the same card from 2.81 to 12.85 tokens/s.

Before the two fixes2.81
After12.85

Its furthest reach: GLM-5.3-Flash (a 93 GB quantisation, 320B parameters) ran on 42 GB of combined memory, well below the roughly 102 GB its publisher gives as a practical minimum, at 1.18 tokens/s, with a 38.7% cache hit rate. Slow, but it loaded and answered correctly.

became

Strata-HotRod · what was built

Pin in segments, give them back. Pinning the hottest experts in memory had lost in solid.cpp, because pinned pages cannot be reclaimed and starve everything else. HotRod page-locks its RAM tier in segments (STRATA_PIN_SEGS) and releases them when memory is needed. A different mechanism on a different engine: +9% on the 3060 PC

Link budgeting. The three links (SSD→RAM, RAM→card, SSD→card) are budgeted like capacities, and every step reports the bytes moved per link per token. A change that raises the hit rate but pushes more bytes over a saturated link does not count as a win.

Long prompts, one layer at a time. The prompt passes one layer at a time, so each layer's experts are read from the SSD once rather than once per piece of the prompt, with direct reads that bypass the page cache.

8,554-token prompt read in 16.9 s262K context fits45K-token conversation back in 0.4 s

From 64K tokens the attention's K/V streams from RAM while 32K tokens stay on the card, and a long conversation's state is saved to the SSD and reloaded instead of being read again.

Chapter 4

Measure it like evidence

Most of what solid.cpp contributed is not a feature but a way of working, and its mistakes taught it as much as its wins.

solid.cpp · what it found

Each fix below was its own before/after on the same hardware, with the same prompt and settings except the thing measured:

Frozen expert-cache bug fixed+65%
Cache fed by prediction, not history+41%
Overlapped prefill uploads+36.0%
Expert cache vs naive CPU offload+31.3%
MTP speculative decoding+28.1%
Empirical placement search+21.6%
Prefetch double-buffer+12.7%
Real placement optimum+10.0%

Defaults were chosen by paired runs, three rounds each, with a control alongside (Gemma-4):

DefaultEvidenceRounds won
Neuron subsetting off unless calibrated on+50%24 of 24
Draft depth 4 (acceptance 0.61 against 0.40)+22%22 of 24
Draft confidence gate p_min 0.5+13%19 of 24
Probabilistic draft acceptance on (off is −9%)+9%20 of 24

Wrong decisions came from the order of the tests. The draft was eliminated before it was configured; a prefill number (42.3 against 48.5 tok/s) switched prefetch off for every decode stage; the acceptance mode was chosen 2,000 lines after the depth it decides. Eight faults were found along the way, among them an illegal memory access with lazily committed K/V, an out-of-memory in CUDA graph capture, and a skipped calibration stage that cached the launch value as if it were a measurement. A "+21% to +50%" gain from three single runs was retracted as noise.

became

Strata-HotRod · what was built

The test ledger. Every decision in SPEC.md stays untested until a row in the ledger holds a measurement on the target PC, and a decision whose test fails is reopened, whoever made it. Comparisons use alternated A/B pairs with a control, and every answer is read by a person.

1 · HypothesisOne idea, one switch, one expected effect, a named test.
2 · Paired A/BSame prompts, alternated runs, an identical-config control.
3 · Read the answersSpeed bought with broken text does not count.
4 · LedgerA row with the measurement, the PC and the date.
5 · Keep or retractA failed test reopens the decision. Noise is retracted in writing.

Several October commits come from systematic code review: hangs on error paths, an image-job deadlock, a batch-state bug in the CUDA decode path, a read past a tensor's storage.

Install HotRod

Installing Strata-HotRod

HotRod is Strata plus the changes in this repository, so the engine is built from Strata with HotRod's files laid over it. This is the Qwen3.8-Flash-Next build; the DeepSeek port has its own notes in hotrod-deepseek/.

You needDetail
Graphics cardNVIDIA, with a recent driver and the CUDA 13 toolkit (neither is installed for you)
Compilergcc-toolset-13 (Rocky Linux 9; other distributions are untested)
Python3.10 or newer with venv. Rocky/Alma/RHEL 9 ship 3.9, which is too old: install python3.12 first
DiskNVMe with about 137 GB free for IQ3_S on a PC whose RAM cannot hold the experts (84 GB download, a 50 GB copy of the experts, room for the draft layer). Setup refuses to start below this
MemoryMeasured on 30 GB. Setup says it wants 64 GB for IQ3_S; naming the model is the consent

Install the prerequisites

sudo dnf install -y git gcc-toolset-13 python3.12 python3.12-pip

Get Strata-HotRod

This page is a legacy copy of the 18 Nov 2026 write-up, which installed HotRod as a patch over Strata commit 477ac13c. That route is superseded: main of Strata-HotRod is the complete engine.

git clone https://github.com/sangharshadhyeta/Strata-HotRod.git
cd Strata-HotRod

Build and set up

--build compiles HotRod's engine; without it setup downloads upstream's, which lacks these changes. It also downloads the learned look-ahead's trained state (5.4 MB, SHA-256 checked) into data/.

scl enable gcc-toolset-13 -- ./setup.sh --model IQ3_S --context 131072 --build --yes --no-start

For 262K context set --max-context 262144 in the config's args. --models-dir /path/on/nvme puts the model files elsewhere.

Run it, inside a memory limit

Cap the server at 94% of RAM: two uncapped runs once froze the test PC. On your own PC, add --host 0.0.0.0 --api-key YOUR_KEY only if you need access from other machines.

systemd-run --scope -p MemoryMax=$(awk '/MemTotal/ {printf "%dK", $2 * 0.94}' /proc/meminfo) -p MemorySwapMax=0 \
  .venv/bin/python serve/server.py --engine strata --config strata-iq3_s.json --port 8095

Open it

When it prints ready: http://127.0.0.1:8095/v1, open http://127.0.0.1:8095. The first hour is the engine fitting itself to your PC (VRAM reserve, RAM tier, which experts sit where), so it starts slower and speeds up.

What was and was not tested. On a fresh clone of Strata at 477ac13c the patch applies, all 55 changed Python files compile, every source file listed in CMakeLists.txt exists (the few absent paths are generated, fetched at build, or guarded by an existence test), the headers the changed C++/CUDA files include resolve, and all 43 setup tests that need no graphics card pass. The original install notes (hotrod-qwen/PRODUCT-README.md) were tested on 13 Nov on an RTX 3060, Rocky Linux 9, CUDA 13.3 up to setup's disk check. The 84 GB model download, the compile and the first start from a patched clone were not run.
